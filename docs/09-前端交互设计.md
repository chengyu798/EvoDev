# 前端交互设计

## 1. 设计目标

EvoDev 面向软件问题诊断与修复场景，前端采用 Cursor/Devin 风格的 Agent 工作台。用户能够在同一个会话中提出问题、查看计划、确认执行，并持续追踪 Agent 的可验证工作过程。

核心原则是“先理解，再规划，后执行；过程透明，结果可追溯”。解释性对话不应误触发代码修改，所有实际修复都必须经过用户确认。

## 2. 整体布局

运行页面采用可折叠的三栏工作台：

- 左栏：历史会话，按时间分组展示。
- 中栏：Agent 对话、计划确认和执行进度，是主要工作区域。
- 右栏：证据抽屉，按需查看测试、代码变更、日志和运行结果。

左右侧栏均可拖拽调整宽度。左栏建议限制在 220～420 像素，右栏建议限制在 360～720 像素；双击分隔线恢复默认宽度，并将用户的宽度偏好保存在本地。移动端不使用拖拽，侧栏改为覆盖式抽屉。

## 3. 视觉主题

采用“天空蓝 + 暖白”的明亮主题：

- 天空蓝：主要操作、选中状态、焦点状态和当前工作节点。
- 暖白：页面和内容区域背景，降低长时间使用的视觉疲劳。
- 奶油黄：少量用于提醒或等待状态。
- 薄荷绿：成功状态。
- 珊瑚红：失败、风险和需要关注的状态。
- 深墨色：正文和标题文字，保证对比度与可读性。

界面保持清晰、轻量的卡片层级，避免过暗背景和过度装饰。中栏对话区域保持宽松，左右栏和证据内容采用更紧凑的密度。

## 4. 会话、消息与运行

采用“会话—消息—运行”三级模型：

- 会话：绑定一个固定仓库，承载一项持续任务及其完整上下文。
- 消息：保存用户需求、补充要求、问题询问和 Agent 回复。
- 运行：一次经过确认的修复执行，单独保存状态、代码变更、测试结果和轨迹。

同一会话可以包含多轮对话和多次运行。用户追加要求时，保留旧运行及其证据，并在同一会话中创建新的运行记录，便于比较和回溯。一个会话创建后不能切换仓库；处理其他仓库必须新建会话。

## 5. 首页与输入框

首页中间区域展示当前项目状态、最近活动和使用提示；底部固定任务输入框，首页与运行页面保持在相同位置。输入框支持提交初始需求，也支持在执行期间补充要求，预留后续对话入口。

创建会话时选择最近使用的项目或输入仓库路径。首次提交后由 Agent 生成简短中文标题，用户可以手动重命名；用户手动修改后，系统不再自动覆盖标题。

## 6. 历史会话

历史栏展示会话而不是单次运行，并按“今天、昨天、更早”分组。每个会话显示标题、项目名称、最近状态和最近更新时间。

每个会话提供独立的“归档”按钮和确认操作。归档只从默认历史列表中隐藏，不删除数据库记录、消息、运行、输出或检查点；在归档视图中可以恢复会话。归档与恢复均以会话为单位。

## 7. 意图识别与权限边界

对话入口增加保守的意图识别与执行路由：

- 解释原因、询问状态、查看结果：进入只读问答，不修改代码、不运行有副作用的操作。
- 明确要求修复、实现、重构或执行测试：进入规划流程。
- 意图不明确：先向用户确认，不擅自执行。

只读问答 Agent 可以读取当前仓库文件、Git 状态和已有测试结果，以真实项目证据回答问题，但不能写入源码、提交 Git、安装依赖或执行明显有副作用的命令。页面应明确标识当前处于“问题解答”还是“代码处理”模式。

## 8. 先规划后执行

用户明确提出处理要求后，规划 Agent 先进行只读分析，可运行基线测试和静态诊断，生成计划但不修改代码。计划至少包含：问题判断、预计修改文件、实施步骤、验证方式、风险和诊断依据。

计划生成后在中栏直接展示，并提供醒目的“启动修复”按钮。只有用户确认后才进入代码修改流程；执行期间提供“停止运行”按钮。

用户可以继续对话调整计划，例如增加测试、删除步骤或限制数据库变更。Agent 根据反馈生成新的计划版本，保留版本记录并突出本次变化。实际运行必须绑定用户确认的计划版本。

## 9. Agent 轨迹与可读输出

采用混合展示方式：

- 执行过程中实时展示当前状态、工具调用、处理文件和测试进度。
- 每个 Agent 在完成阶段任务后输出结构化中文总结。
- Agent 按角色分开显示，例如分析 Agent、开发 Agent、失败分析 Agent、审查 Agent 和系统消息。
- 内容必须来自真实运行轨迹，不使用虚构进度。

输出统一按“结论—执行内容—结果—下一步”组织。工具名称、参数、返回结果、文件变更和测试日志等可验证信息可以展开查看；大段代码和原始日志默认折叠。不得展示模型内部思维过程，只展示可验证的执行轨迹和结果。错误信息以易懂中文说明，同时保留原始错误文本供排查。

## 10. 证据抽屉

右侧证据抽屉按需展示完整证据，并支持用户锁定、切换或关闭。未锁定时根据工作状态智能切换：

- 开始运行：当前节点和状态。
- 测试阶段：测试输出和测试报告。
- 代码修改阶段：代码差异和修改文件。
- 失败阶段：失败原因、原始错误和诊断信息。
- 完成阶段：结果摘要、最终差异和验证结论。

用户一旦手动锁定或切换内容，自动切换不得覆盖用户选择。

## 11. 追加要求与再次运行

执行期间，用户可以在底部输入框补充要求。提交后显示确认选项：等待当前运行完成，或取消当前运行后立即重新规划并运行。新要求与原任务描述合并，创建新的运行记录；旧运行、证据和结果继续保留在当前会话中。

## 12. 响应式规则

桌面端默认使用三栏工作台，并允许折叠左右栏以扩大中栏。窄屏设备优先保证中栏对话和底部输入框可用；历史栏与证据抽屉改为覆盖式抽屉，通过按钮打开和关闭。抽屉打开时保留当前上下文，关闭后不丢失浏览位置或筛选状态。
