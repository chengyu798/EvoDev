本文区分“已有真实证据”“本次复核”和“尚未完成的实验”，避免把演示成功等同于普遍有效。
历史实验使用当时的模型与 Prompt；后续代码修改不意味着历史结果已在新代码上重新验证。

## 1. 两个可重复演示的任务

| 示例 | 需要修复的行为 | 修复前结果 | 验收约束 |
|---|---|---|---|
| `examples/buggy-calculator` | `add` 返回两个整数之和 | 2 个测试失败 | 函数签名和测试文件不变 |
| `examples/buggy-text-normalizer` | `slugify` 去首尾空白、转小写、连续空白转单个连字符 | 2 个测试失败 | 函数签名和测试文件不变 |

2026 年 9 月 5 日本地重新执行以下命令，结果为 `4 failed in 0.02s`。这是缺陷样例的预期
失败，不是 EvoDev 回归测试失败。本次只复核缺陷基线，没有调用外部模型。

```bash
PYTHONDONTWRITEBYTECODE=1 uv run pytest -q -p no:cacheprovider \
  examples/buggy-calculator examples/buggy-text-normalizer
```

计算器完整操作见[手动测试指南](04-手动测试指南.md)。文本规范化任务可按以下命令准备；
每次演示都新建目录，不复用已经修好的工作区：

```bash
TEXT_DEMO_DIR="$(mktemp -d /tmp/evodev-demo.XXXXXX)"
cp examples/buggy-text-normalizer/text_normalizer.py "$TEXT_DEMO_DIR/"
cp examples/buggy-text-normalizer/test_text_normalizer.py "$TEXT_DEMO_DIR/"
git -C "$TEXT_DEMO_DIR" init
git -C "$TEXT_DEMO_DIR" add text_normalizer.py test_text_normalizer.py
git -C "$TEXT_DEMO_DIR" -c user.name="EvoDev Demo" \
  -c user.email="demo@evodev.local" commit -m "初始化文本规范化错误示例"
```

通过 CLI 提交任务；模型调用会产生费用，不能保证每次结果相同：

```bash
uv run evodev repair \
  --repository "$TEXT_DEMO_DIR" \
  --issue-title "修复文本规范化错误" \
  --issue-body "修复 slugify：去除首尾空白、转换为小写，把连续空白替换为单个连字符。保持函数签名和测试文件不变。" \
  --test-command "pytest -q" \
  --max-iterations 3
```

## 2. 五分钟演示顺序

1. 展示临时 Git 仓库和失败测试，说明问题可以复现。
2. 通过 CLI 提交问题并启动修复。
3. 查看终端中的阶段状态与运行编号。
4. 检查测试证据，对照修复前失败与修复后通过，核对 Reviewer 结论。
5. 检查 Patch，说明改动发生于隔离工作区；原仓库的 `git status --short` 应无输出。
6. 展示历史经验和 Prompt 评测记录，说明失败候选会被拒绝，并非所有候选都能升级。

## 4. Experience 对照实验的验收口径

正式声称经验有效之前，需要固定样例代码、模型、Prompt、测试命令、最大迭代次数以及一份
经验快照。对每个相同初始提交分别执行“关闭经验”和“启用固定经验”；评测期间不将新经验
回流到下一条样例，不启动 Prompt 进化。保留失败和基础设施错误，不能只挑成功结果。

| 指标 | 计算方式 |
|---|---|
| 任务成功率 | 测试与审查均通过的任务数 / 全部尝试任务数 |
| 测试通过率 | 最终测试通过的运行数 / 全部尝试运行数；不是逐测试用例通过率 |
| 平均重试次数 | 各运行 `retry_count` 之和 / 运行数 |
| Token 用量 | 输入与输出分别汇总，并报告两者总量 |
| 执行耗时 | 全部运行平均耗时，并单独列出成功运行平均耗时 |

原任务清单要求 5～10 个不同 Bug；目前仓库提供 2 个不同 Bug，重复跑同一个任务不能冒充
新增样例。现有数据只能证明闭环可运行，不能证明普遍的软件修复效果。

本次在获得数据发送授权后，使用 `deepseek/deepseek-v4-flash` 完成四次真实运行。两个样例
交替执行组别，失败也会计入分母。固定 Prompt 的 SHA-256 为
`fa5ac998a1c70fc8070ad4527eae45b4d05bc2cc3efef5a1eb1d5d1cacf521c3`。

| 指标 | Baseline | Experience |
|---|---:|---:|
| 任务成功率 | 2 / 2（100%） | 2 / 2（100%） |
| 测试通过率 | 2 / 2（100%） | 2 / 2（100%） |
| 平均重试次数 | 0 | 0 |
| 输入 Token | 35,605 | 56,596 |
| 输出 Token | 4,301 | 5,697 |
| 总 Token | 39,906 | 62,293 |
| 平均耗时 | 21,123 ms | 25,463 ms |

两组都成功，因此这次实验没有证明 Experience 能提高成功率或减少重试。Experience 组总
Token 比 Baseline 高约 56.1%，平均耗时高约 20.5%；样本过小，不能据此推断普遍负效果，
但也不能把结果包装成经验优化收益。模型单价没有配置，报告将费用保留为“未配置”，没有
用虚假的零费用代替未知值。

更重要的是，文本规范化任务也命中了计算器经验。两者只共享 `task:bug_fix`、`ext:py` 等
通用标签，说明当前“任意标签重合即可命中”的策略会注入不相关经验。这是本次对照发现的
真实局限：后续应过滤通用标签或设置有效标签的最小匹配条件，再扩大样本复测。

原始逐次报告保存在 `outputs/experience-comparison-20260905.json`，其中包含四个运行编号、
固定 Prompt、经验快照、Token、耗时、测试结果和经验命中编号。该目录是本地运行输出，不
默认提交 Git；本节保留可审计摘要。

项目已提供固定样例、基础 Prompt 和经验快照的对照入口。默认命令只做预检，不会调用模型：

```bash
uv run python -m evodev.evaluation.comparison \
  --experience-file examples/experience-snapshots/calculator.json
```

确认数据发送范围和模型费用后，显式添加 `--execute` 执行四次真实运行；报告逐次落盘，失败
也计入分母，已有报告不会被覆盖：

```bash
uv run python -m evodev.evaluation.comparison \
  --experience-file examples/experience-snapshots/calculator.json \
  --output outputs/experience-comparison-复测.json \
  --execute
```

程序拒绝覆盖已有报告。计算器用于验证匹配经验的影响，文本规范化样例作为不相关经验的
负向检查；本次负向检查实际发现了错误注入。这仍是两个任务的小样本检查，不能代替 5～10
个不同缺陷的扩展实验。

## 5. 可用于简历的项目描述

**EvoDev：基于 LangGraph 的多智能体软件修复系统**

- 设计 Analyst、Developer、Failure Analyzer、Reviewer 协作工作流，串联问题分析、受控
  代码修改、真实测试与补丁审查，限制最多三轮修复并输出标准 Git Patch。
- 使用 Docker 与独立 Git 工作区隔离执行，限制网络、资源、超时和输出大小；通过
  PostgreSQL 保存业务数据与 LangGraph 检查点，保留可追溯的测试与 Agent 运行证据。
- 实现失败经验提取、标签检索与效果反馈；使用独立 Worker 生成候选 Prompt，通过相同
  Bug 的 A/B 评测和防回归门禁决定升级、拒绝及回滚。
- 构建 FastAPI 任务接口，支持后台运行、状态查询和完整证据聚合。

面试可引用的真实案例：两个 Bug 上完成四次 Prompt A/B，当前版本成功 2 次、候选成功
1 次，系统拒绝退化候选。不要写“成功率提升 X%”“自动修复任意项目”“生产级多租户”
或“模型自我训练”，现有证据不支持这些表述。

## 6. 后续 Roadmap

| 优先级 | 方向 | 完成标准 |
|---|---|---|
| 近期 | 扩充固定 Bug 集和多次重复实验 | 覆盖 5～10 个不同缺陷，提交可审计的对照汇总 |
| 近期 | 可靠的长任务与中断恢复 | 规划、取消、崩溃恢复有持久状态和故障注入测试 |
| 中期 | GitHub 集成 | 授权后读取 Issue，在人工确认后创建 PR，不默认推送 |
| 中期 | 多语言沙箱 | 为每种语言提供独立镜像、测试适配和安全验收 |
| 中期 | 检索策略评测 | 比较标签与向量检索，先证明收益再增加组件 |
| 长期 | 工作流与 Skill 进化 | 固定权限边界，离线评测、防回归与可回滚后才启用 |
| 长期 | 多用户与部署 | 身份认证、授权隔离、配额、审计及沙箱安全加固 |

Roadmap 是未来范围，不应在当前功能清单或简历中写成已经完成。
