# 前端设计参考

## 1. 调研目标

本次调研用于指导 EvoDev 从传统表单工作台调整为明亮的对话式 Agent 工作台。参考对象以
AI 编程和 Agent 产品的官方说明为主，重点观察任务输入、上下文补充、执行反馈、证据复查
和历史任务组织方式，不直接复制任何单一产品的视觉设计。

## 2. 设计关键词

- 对话优先的 Agent 工作台（Chat-first agent workspace）
- 历史任务侧栏与当前会话主区（Master-detail session sidebar）
- 携带仓库上下文的输入框（Composer with repository context）
- 实时执行时间线（Live execution timeline）
- 证据优先的结果复查（Evidence-first result review）
- 对话与运行产物组合展示（Conversation with artifacts）
- 摘要先行、细节按需展开（Progressive disclosure）
- 暖白背景与日光强调色（Soft daylight palette）

## 3. EvoDev 设计方向

EvoDev 使用“历史对话侧栏 + 对话式任务区 + 结构化证据区”的混合结构。页面默认进入新
任务，用户先描述需要解决的代码问题，再关联本地 Git 仓库；任务名称可以自动生成，测试
命令、修改约束和最大修复次数默认折叠。运行详情以用户任务和 EvoDev 响应建立上下文，再
显示工作流进度、测试证据、智能体轨迹和代码差异。

视觉上使用暖白作为页面背景，日光黄作为品牌与主要操作色，低饱和暖灰建立信息层级，绿色
和红色只表达真实运行状态。页面保持低阴影、清晰边界和充足留白，不使用暗黑科技风、霓虹
发光或多种竞争性的强调色。

## 4. 可落地原则

1. 一个主要入口：首屏让问题描述成为视觉主角，仓库和运行参数渐进补充。
2. 历史按任务组织：侧栏展示任务标题、仓库、状态和时间，只有用户主动选择时才打开旧任务。
3. 状态与证据分层：对话区域说明当前结论，工作流展示进度，选项卡承载详细日志和代码差异。
4. 保留人工控制：重新运行、取消运行和复查补丁都由用户主动触发，系统不修改原始仓库。
5. 不伪造连续对话：当前后端没有消息会话和追问接口，因此不展示无法提交的聊天输入框。

## 5. 官方参考

- [GitHub Copilot 编程智能体任务创建](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github)：自然语言、仓库、分支和附件共同组成任务上下文。
- [GitHub Copilot 智能体任务管理](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents)：展示会话列表、进度、日志、Token 和耗时。
- [Replit Agent 任务系统](https://docs.replit.com/core-concepts/agent/task-system)：使用任务线程、隔离工作区、工作日志和人工应用结果。
- [Devin 会话工具](https://docs.devin.ai/work-with-devin/devin-session-tools)：在统一进度中串联命令、代码编辑和浏览活动。
- [v0 快速入门](https://api2.v0.dev/docs/quickstart)：通过自然语言开始任务，并在同一对话中持续迭代。
- [OpenAI Canvas](https://openai.com/index/introducing-canvas/)：把对话与可独立查看、编辑和恢复的产物结合。
- [Claude Artifacts](https://support.anthropic.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)：在对话旁展示产物并支持版本切换。
