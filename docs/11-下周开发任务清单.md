# EvoDev 下周开发任务清单

## 1. 文档信息

- 计划周期：2026 年 9 月 7 日至 9 月 13 日
- 当前状态：9 月 7 日至 9 日任务已确认，其余日期暂不安排
- 总体目标：提升经验检索准确性和工作流可靠性，同时扩充可重复运行的评测样例

## 2. 优先级

下周已确认的三项任务全部按 `P0` 处理：

1. 优化经验检索，避免无关经验影响智能体决策。
2. 增强任务中断恢复与取消能力，提高长任务可靠性。
3. 扩充统一、可重复的 Bug 评测数据集。

## 3. 9 月 7 日：优化经验检索

### 3.1 要解决的问题

当前经验检索只要存在任意标签重合就可能召回经验。`task:bug_fix`、
`ext:py` 等通用标签会让不同类型的任务互相命中，导致无关内容被注入
Agent Prompt。

### 3.2 任务清单

- [x] 梳理现有经验标签、查询条件和质量分排序逻辑。
- [x] 对任务类型、错误类型、文件名、函数名和技术特征设置不同权重。
- [x] 对过于宽泛的通用标签降权，必要时不将其作为独立命中依据。
- [x] 设置最低匹配分数，低于阈值时不返回经验。
- [x] 记录经验被召回的原因、匹配特征和最终分数。
- [x] 补充正确命中、错误命中、无结果和低质量经验降权测试。

### 3.3 验收标准

- [x] 计算器任务能够召回与计算器问题相关的经验。
- [x] 文本规范化任务不会因通用标签而误用计算器经验。
- [x] 每条检索结果都能说明“为什么命中”。
- [x] 现有经验使用次数、效果反馈和质量分逻辑不发生回归。

完成情况：检索现按错误类型、文件名、函数名、技术特征、任务关键词、任务类型和扩展名
分级加权，再使用经验质量分修正最终得分；低于 `2.5` 的候选不会返回。`task:bug_fix`、
`ext:py` 等通用标签不能独立构成有效命中，`py/python` 也不再作为普通关键词重复计分。
每次运行会生成 `experience-retrieval.json`，保存查询标签、命中特征、中文原因、相关性分、
质量系数和最终分数。自动化测试与真实 PostgreSQL 集成测试均已通过。

## 4. 9 月 8 日：增强中断恢复与取消能力

### 4.1 要解决的问题

长时间修复任务可能遭遇 API 服务重启、模型调用异常或用户主动取消。系统需要
确保任务状态、Docker 容器、临时工作区和持久化记录保持一致。

### 4.2 任务清单

- [ ] 验证 API 服务重启后的 LangGraph Checkpoint 恢复行为。
- [ ] 定义可恢复、不可恢复和需要用户确认的任务状态。
- [ ] 完善任务取消接口和状态转换。
- [ ] 取消时终止对应的 Docker 容器，并按规则处理临时工作区。
- [ ] 确保节点重放不会重复生成产物、重复累加经验使用次数或重复提交状态。
- [ ] 增加服务重启、中断恢复、用户取消、清理失败和重复请求测试。

### 4.3 验收标准

- [ ] 任务中断后可以从已保存的检查点继续，或以明确的错误状态结束。
- [ ] 用户取消后不再调用后续智能体或执行测试。
- [ ] 取消后不遗留运行中的任务容器。
- [ ] 重复执行同一节点不会产生重复业务数据。

## 5. 9 月 9 日：扩充评测数据集

### 5.1 目标

将当前两个 Bug 样例扩充为一组可固定、可恢复、可自动验证的小型评测集，
为后续 Experience 和 Prompt 对照实验提供可信输入。

### 5.2 任务清单

- [ ] 将 Bug 样例扩充至少 8 个，视当日进度扩充至 10 个。
- [ ] 覆盖计算错误、字符串处理、边界条件、异常处理和数据转换等类型。
- [ ] 每个样例固定初始代码、问题描述、测试命令、限制条件和预期结果。
- [ ] 为每个样例提供可重复初始化和清理机制。
- [ ] 建立统一的样例清单与机器可读配置。
- [ ] 对每个样例执行缺陷基线测试，确认测试在修复前稳定失败。
- [ ] 区分业务修复失败、模型调用失败和基础设施失败。
- [ ] 生成统一格式的基线评测报告。

### 5.3 验收标准

- [ ] 至少 8 个样例都能一键恢复至相同初始状态。
- [ ] 每个样例的修复前测试结果可重复。
- [ ] 样例不依赖未声明的本地工具或全局环境。
- [ ] 评测报告能明确说明样例类型、基线结果和失败分类。
